# 프롬프트 로그 작성 가이드

팀원 모두 같은 양식으로 프롬프트 로그를 남기기 위한 규칙이다. 양식은 `02_프롬프트로그_템플릿` 페이지를 그대로 복사해서 쓴다.

---

## 노션 세팅 (팀장 1회)

1. 팀 페이지 안에 **표(데이터베이스)** 를 만들고 이름을 `프롬프트 로그`로 한다.
2. 아래 속성을 추가한다.

| 속성 이름 | 속성 종류 | 선택지 |
| --- | --- | --- |
| 작업명 | 제목 | - |
| 작성자 | 사람 | - |
| 작업 기간 | 날짜 (종료일 포함) | - |
| 작업 분류 | 선택 | 기획 / 디자인 / 영상 / 개발 / 데이터 / 문서 |
| 사용 AI | 다중 선택 | Claude / ChatGPT / Gemini / Grok / Kling / 기타 |
| 상태 | 상태 | 진행 중 / 완료 |
| 결과물 링크 | URL | - |

3. 데이터베이스 우측 상단 `새로 만들기 ▾` → `+ 새 템플릿` → 템플릿 본문에 `02_프롬프트로그_템플릿` 내용을 붙여넣고 이름을 `프롬프트 로그`로 저장한다.
4. 템플릿 메뉴에서 `기본값으로 설정`을 누르면, 팀원이 `새로 만들기`만 눌러도 양식이 자동으로 채워진다.

> 데이터베이스 속성을 쓰는 경우, 템플릿 맨 위 "작성자·작업 기간…" 표는 지워도 된다(속성과 중복).

---

## 복붙하는 방법

1. `02_프롬프트로그_템플릿.md` 파일을 열고 전체 선택(Ctrl+A) → 복사(Ctrl+C).
2. 노션 빈 페이지 본문을 클릭하고 붙여넣기(Ctrl+V). 제목·표·코드 블록·체크박스가 자동으로 노션 블록으로 바뀐다.
3. 맨 위 `# [작업명] 프롬프트 로그` 줄은 페이지 제목으로 옮기고 지운다.

---

## 작성 규칙

1. **프롬프트는 원문 그대로.** 요약하지 말고 실제 입력한 문장을 코드 블록(```text)에 붙여넣는다. 변수는 `{channel_name}`처럼 중괄호로 표시한다.
2. **버전은 바뀐 점이 있을 때만 올린다.** v1.0 → v1.1(작은 수정) → v2.0(구조 변경). 버전마다 `바꾼 점 / 결과`를 꼭 쓴다.
3. **실패도 남긴다.** 안 된 시도와 롤백도 기록한다. "왜 안 됐는지"가 가장 쓸모 있는 정보다.
4. **환각은 표로 정리한다.** `문제 → 발생 상황 → 원인 → 해결 프롬프트 → 결과` 순서를 지킨다.
5. **결과는 숫자나 확인 가능한 사실로.** "좋아졌다" 대신 "철자 오류 0건", "콘솔 오류 0건", "10번 재생성 모두 로고 유지"처럼 쓴다.
6. **이미지·영상 작업은 결과물 캡처를 붙인다.** 버전별 결과 아래에 이미지 1장씩.
7. **비밀값 금지.** API 키, 비밀번호, 개인 이메일·연락처는 `***`로 가린다.
8. **해당 없는 칸은 지우지 말고 `-`로 둔다.** 팀원끼리 같은 칸을 비교하기 쉽게 하기 위해서다.

## 섹션별 쓰는 법

| 섹션 | 무엇을 쓰나 | 분량 |
| --- | --- | --- |
| 1. 작업 개요 | 목적, 산출물, AI에게 맡긴 것과 맡기지 않은 것 | 4줄 |
| 2. 작업 흐름 | 단계마다 `작업`과 `환각·품질 제어` 한 쌍 | 단계당 2~3줄 |
| 3. 프롬프트 버전 기록 | 프롬프트 원문 + 결과 + 문제 + 다음 조치 | 버전당 자유 |
| 4. 환각·문제 해결 기록 | 문제 하나당 표 한 줄 | 3줄 이상 |
| 5. 효과 있었던 패턴 | 다른 팀원이 바로 따라 쓸 수 있는 요령 | 2~4개 |
| 6. 최종 결과 | 완료 항목 체크 + 감수한 한계 | 자유 |
| 7. 핵심 교훈 | 한 문장짜리 교훈 | 2~3개 |

## 작성 예시 (일부)

### ▶ 2단계: 경험 분석 결과를 JSON으로 받기 (Claude)

- **작업:** 사용자가 쓴 경험 글에서 역량 키워드와 근거 문장을 뽑는다.
- **환각·품질 제어:** 원문에 없는 성과 수치를 지어내지 않도록 "원문 문장만 근거로 인용"을 프롬프트 맨 위에 고정했다.

### v1.0 — 최초 프롬프트

```text
이 경험에서 무역 직무 역량을 분석해줘.
```

- **결과:** 줄글로 답해서 화면에 넣을 수 없음.
- **문제점:** 출력 형식 미지정, 원문에 없는 "매출 20% 상승" 같은 수치 생성.
- **다음 조치:** JSON 형식 강제 + 원문 인용 규칙 추가.

### v2.0 — JSON 강제 + 근거 인용 규칙

```text
당신은 무역업 채용 담당자입니다.
아래 경험 글만 근거로 역량을 분석하세요. 글에 없는 수치·성과는 만들지 마세요.

[경험 글]
{experience_text}

[출력 - JSON만 반환, 백틱 없음]
{"competencies": [{"name": "", "evidence": "원문 문장 그대로"}]}
```

- **바꾼 점:** 역할 지정, 근거 인용 규칙, JSON 스키마 추가.
- **결과:** 10회 실행 중 파싱 오류 0건, 지어낸 수치 0건.

| 문제 (Pain Point) | 발생 상황 | 원인 | 해결 프롬프트·조치 (Solution) | 결과 (Impact) |
| --- | --- | --- | --- | --- |
| 성과 수치 날조 | 원문에 없는 "매출 20% 상승" 출력 | 빈칸을 그럴듯하게 채우려는 경향 | "글에 없는 수치·성과는 만들지 마세요" 추가 | 날조 수치 0건 |
| JSON 파싱 실패 | 응답을 ```json 으로 감싸서 반환 | 마크다운 습관 | "JSON만 반환, 백틱 없음" 명시 | 파싱 오류 0건 |
